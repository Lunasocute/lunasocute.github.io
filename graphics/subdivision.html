Catmull-Clark Subdivision

Luna Tian · CIS 4600/5600 Interactive Computer Graphics, University of Pennsylvania

Overview

A polygon mesh editor in the style of Maya or Blender, written in C++ with Qt and OpenGL. Meshes are stored in a half-edge data structure, which makes it possible to walk across a surface and change its topology directly. On top of that structure, Catmull-Clark subdivision turns a coarse mesh into a smoother one with many more faces.

Functions

  • OBJ import: loads closed meshes with faces of any number of sides and links up every half-edge with its opposite.
  • Mesh inspection: select any vertex, half-edge, or face from a list and see it highlighted. Hotkeys step to the next half-edge, its opposite, its face, or its vertex.
  • Editing: move vertices, recolor faces, add a vertex at an edge’s midpoint, and triangulate a face.
  • Subdivision: one button runs a level of Catmull-Clark on the whole mesh, and it can be pressed repeatedly.

How It Works

Half-edge mesh

Each edge is stored as two half-edges, one for each direction. A half-edge points to its next half-edge around the face, its opposite (“sym”), its face, and the vertex it ends at. Vertices and faces each keep a pointer to one half-edge.

Neighbors can then be reached by following pointers, with no searching. For example, repeating next → sym from a half-edge that points to a vertex visits every edge and face around that vertex.

One level of Catmull-Clark

1. Face points. Each face gets a new point at the average of its vertices.

\[ \mathbf{f} = \frac{1}{k}\sum_{i=1}^{k} \mathbf{v}_i \]

2. Edge points. Each edge is split once by a new vertex, placed using its two endpoints and the face points on both sides. The position has to be computed before the split, since splitting changes the pointers it depends on.

\[ \mathbf{e} = \frac{\mathbf{v}_1 + \mathbf{v}_2 + \mathbf{f}_1 + \mathbf{f}_2}{4} \]

3. Smooth the original vertices. Each original vertex moves toward its surroundings. Here \(n\) is the number of edges meeting at the vertex, and the sums run over its \(n\) adjacent edge points and face points.

\[ \mathbf{v}' = \frac{n-2}{n}\,\mathbf{v} + \frac{\sum_i \mathbf{e}_i + \sum_i \mathbf{f}_i}{n^2} \]

4. Quadrangulate. A face with \(k\) sides is rebuilt as \(k\) quads meeting at its face point. Two new half-edges are added per quad, and the half-edges going into and out of the center are saved so that neighboring quads can be paired as opposites once the loop is done.

The first level turns the cow’s triangles into three quads each. After that, every quad becomes four, so the face count grows by a factor of four per level.

Performance

Every face, edge, and vertex is handled a fixed number of times per level, and each lookup is either a pointer or a hash map access. A level’s running time should therefore grow in proportion to the mesh size. The measurements on the cow agree: each time the output grows fourfold, the time grows by 4.4 to 4.8 times.

FacesTimePer output face
5,804 → 17,41251 ms2.9 µs
17,412 → 69,648229 ms3.3 µs
69,648 → 278,5921,105 ms4.0 µs
278,592 → 1,114,3684,857 ms4.4 µs

All four levels take about 6.2 seconds in total. The cost per face rises slightly as the mesh grows, which may come from memory access as the mesh gets larger, though I did not profile it. Times come from std::chrono around the subdivision call only, excluding the GPU upload, in a debug build without compiler optimizations.
